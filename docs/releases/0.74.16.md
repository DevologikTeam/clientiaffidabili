# Release 0.74.16 — Docker Build Context Hygiene & pnpm CLI Shim Fix

## Summary
Fixes the Coolify preflight Docker builder failure where `nest build` and `next build` could not resolve their CLI targets inside the container:

- `/app/apps/api/node_modules/@nestjs/cli/bin/nest.js`
- `/app/apps/web/node_modules/next/dist/bin/next`

## Root cause
The project did not have a root `.dockerignore`, so after the local preflight ran `pnpm install`, Docker sent host `node_modules`, `.next`, `dist`, and cache artifacts into the Linux build context. `COPY . .` could then overwrite Linux-created pnpm links/shims with host artifacts and break package CLI resolution.

## Changes
- Added root `.dockerignore` excluding host artifacts.
- API Dockerfile verifies the Nest CLI target before running the build.
- Web Dockerfile verifies the Next CLI target before running the build.
- Fixed web runner `CMD` quoting for the `require.resolve('next')` diagnostic.
- Extended Docker runtime and Coolify preflight static guards to require `.dockerignore` protections.
