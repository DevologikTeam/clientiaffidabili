# 0.74.9 - Docker Runtime Next Dependencies & TypeORM Postgres Metadata Patch 9

## Scopo

Questa patch chiude due problemi emersi dopo il build Docker reale:

1. il container web trovava `server.js`, ma il runtime falliva con `Cannot find module 'next'`;
2. il container API superava il bootstrap Nest, ma TypeORM/Postgres falliva su colonne tipizzate come `Object`, a partire da `SupportTicket.category`.

## Fix web Docker

- Aggiunto `outputFileTracingRoot` in `apps/web/next.config.mjs` per il tracing standalone in monorepo.
- Il runner `apps/web/Dockerfile` continua a copiare `.next/standalone`.
- Il runner copia anche `node_modules` root e app-level dal layer `deps`, così un `server.js` emesso a root può risolvere `next` da `/app/node_modules`.
- Mantenuto il fallback di avvio sia per `apps/web/server.js` sia per `server.js`.

## Fix API TypeORM/Postgres

- Aggiunto `type: 'varchar'` alle colonne TypeORM che usano union type, literal type, type alias o indexed-access types.
- Corretto il caso reale `SupportTicket.category`, più `status`, `priority` e `relatedType`.
- Estesa la patch a tutte le entity con lo stesso rischio, evitando che il container fallisca sul campo successivo dopo `SupportTicket.category`.
