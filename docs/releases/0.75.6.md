# Release 0.75.6 — Local Network Access Prompt Fix

Data: 2026-05-31

## Obiettivo

Eliminare il prompt Chrome "accedere ad altri servizi e app su questo dispositivo" dalle pagine pubbliche. La causa più probabile era una chiamata browser verso endpoint locali o interni, in particolare configurazioni pubbliche basate su `NEXT_PUBLIC_API_URL`/`PUBLIC_API_URL` con valori `localhost` o rete Docker.

## Modifiche

- Il client web non chiama più direttamente `NEXT_PUBLIC_API_URL` per la configurazione analytics pubblica.
- `fetchExternalTrackingConfig()` usa ora una route same-origin:
  - `/api/analytics/public-config`
- Aggiunta route Next server-side:
  - `apps/web/app/api/analytics/public-config/route.ts`
- La route server-side inoltra verso `INTERNAL_API_URL`, senza esporre URL locali al browser.
- Rimosso `NEXT_PUBLIC_API_URL` da:
  - `apps/web/Dockerfile`
  - `docker-compose.yml`
  - `docker-compose.coolify.yml`
- `apps/web/app/api/sales-crm/contact-messages/route.ts` usa solo `INTERNAL_API_URL` server-side.
- `Permissions-Policy` include anche `local-network-access=()`.
- Aggiunto QA anti-regressione:
  - `scripts/qa-local-network-access-guards.js`

## Nota operativa

Dopo il deploy, svuotare cache/browser permission state se il prompt era già stato mostrato su Chrome: Impostazioni sito → autorizzazioni del sito → reimposta autorizzazioni per `clientiaffidabili.it` oppure provare in una nuova finestra/profilo.
