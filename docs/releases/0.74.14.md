# 0.74.14 - Coolify Preflight Windows Standalone Symlink Patch

## Obiettivo

Evitare che `pnpm qa:coolify-preflight` fallisca su Windows durante il build locale Next standalone con errori `EPERM: operation not permitted, symlink ...`, mantenendo comunque il controllo standalone reale dentro Docker/Linux.

## Fix

- `scripts/coolify-preflight.sh` ora esegue il build web locale con `NEXT_DISABLE_STANDALONE=1`.
- `scripts/coolify-preflight.ps1` ora esegue il build web locale con `NEXT_DISABLE_STANDALONE=1`.
- `apps/web/next.config.mjs` ora disabilita `output: standalone` solo quando `NEXT_DISABLE_STANDALONE=1`.
- `apps/web/next.config.mjs` sposta `outputFileTracingRoot` sotto `experimental`, evitando il warning Next `Unrecognized key(s) in object: outputFileTracingRoot`.
- Il build Docker/Coolify continua a usare `output: standalone`, perche il Dockerfile non imposta `NEXT_DISABLE_STANDALONE`.
- Rafforzati i QA statici per garantire che il preflight locale Windows non generi `.next/standalone`, mentre Docker continua a validare il runtime standalone.

## QA

- `node scripts/qa-coolify-preflight-static-guards.js`
- `node scripts/qa-docker-runtime-static-guards.js`
- `node scripts/qa-web-build-static-guards.js`
- `node scripts/qa-api-typeorm-postgres-static-guards.js`
- `node scripts/qa-source-syntax-smoke.js`
- `node scripts/security-secret-scan.js`

## Nota

Il preflight locale su Windows ora verifica compilazione/typecheck web senza standalone. Il test equivalente a Coolify resta il passaggio Docker `build --no-cache api web`, eseguito subito dopo nello stesso comando.
