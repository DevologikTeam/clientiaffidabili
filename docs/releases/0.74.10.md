# 0.74.10 - Docker Runtime Next Root Resolution Patch 10

## Scopo

Questa patch corregge il problema runtime web ancora presente dopo v0.74.9: il container trovava `/app/server.js`, ma quel server standalone non riusciva a risolvere il modulo `next` dal root runtime.

## Fix web Docker

- Aggiunto stage `prod-deps` in `apps/web/Dockerfile`.
- Installate dipendenze production con `pnpm install --prod --filter @clientiaffidabili/web... --frozen-lockfile=false`.
- Il runner copia `node_modules` root e app-level da `prod-deps`, non dal builder/deps di sviluppo.
- Aggiunto `NODE_PATH=/app/node_modules:/app/apps/web/node_modules`.
- Aggiunti symlink root per `next`, `react`, `react-dom` e `styled-jsx` quando il package esiste solo in `apps/web/node_modules`.
- Aggiunta verifica `require.resolve('next')` durante la build del runner e prima dell'avvio del server.
- Mantenuto il fallback di avvio per `apps/web/server.js` oppure `server.js`.

## QA

Rafforzato:

```bash
node scripts/qa-docker-runtime-static-guards.js
```

Il gate ora controlla stage `prod-deps`, `NODE_PATH`, symlink root e verifica `require.resolve('next')`.

## Nota

Il test definitivo resta il rilancio Docker reale. Questa patch chiude specificamente la famiglia `MODULE_NOT_FOUND next` da `/app/server.js`.
