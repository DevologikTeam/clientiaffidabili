# 0.74.18 - Web Healthz & Container Healthcheck Patch 17

## Obiettivo

Correggere il preflight Coolify quando API e web risultano avviati, ma il controllo web fallisce usando la homepage come healthcheck.

## Fix

- Aggiunto endpoint Next dedicato `GET /healthz` in `apps/web/app/healthz/route.ts`.
- Aggiornati `docker-compose.yml` e `docker-compose.coolify.yml` per usare Node `fetch` su `http://127.0.0.1:3000/healthz`.
- Aggiornati `scripts/coolify-preflight.sh` e `scripts/coolify-preflight.ps1` per controllare la health web dal container con Node `fetch`, non con `wget`.
- Default `WEB_HEALTH_URL` aggiornato a `http://localhost:3000/healthz`.
- Aggiornata documentazione `docs/deployment/COOLIFY_PREFLIGHT.md`.
- Rafforzati `qa-coolify-preflight-static-guards.js` e `qa-docker-runtime-static-guards.js`.

## Perché

La homepage pubblica non deve essere usata come readiness probe: può dipendere da rendering, asset, redirect o timing. `/healthz` è leggero, tecnico e stabile.
