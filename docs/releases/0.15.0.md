# Release 0.15.0 — M5-P Provider Integration Design

## Sprint completato

M5-P — Provider Integration Design

## Cosa include

- Blueprint `ProviderAdapter` Openapi-first e multi-provider-ready.
- Blueprint data model provider: `ProviderRequest`, eventi, cost ledger e raw payload vault.
- Registry mapping servizi MVP versionato.
- Lifecycle richiesta provider post-payment.
- Callback e polling idempotenti.
- DTO/evidence model normalizzato.
- Admin provider operations blueprint.
- Security/secrets/retention e raw payload vault blueprint.
- Handoff dettagliato per M5-S.
- Tipi condivisi provider design.
- File TypeScript di design per backend/frontend.
- QA statico `qa:provider-integration-design`.

## Guardrail

- Provider call solo dopo pagamento confermato.
- Nessuna credenziale provider nel browser.
- Nessun raw payload nel report cliente.
- Cost snapshot e mapping version obbligatori.
- Retry automatico solo se safe/idempotente.
- Manual review per servizi compliance, errori paid e payload parziali.
- Produzione provider disabilitata di default.
