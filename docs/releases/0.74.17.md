# Release 0.74.17 - Coolify Preflight DB Schema & Container Health Patch 15

## Fix

Il preflight v0.74.16 costruiva correttamente le immagini API e web, ma l API andava in restart su un database Postgres locale vuoto perche `NODE_ENV=production` disabilitava TypeORM synchronize e `SettingsAdminService.onModuleInit` leggeva `platform_settings` prima della creazione tabella.

## Modifiche

- `apps/api/src/app.module.ts` ora supporta `DATABASE_SYNCHRONIZE` e `DATABASE_LOGGING`.
- `docker-compose.coolify.yml` espone `DATABASE_SYNCHRONIZE` e `DATABASE_LOGGING` con default `false`.
- `scripts/coolify-preflight.sh` e `.ps1` impostano `DATABASE_SYNCHRONIZE=true` solo per il preflight locale.
- Il preflight esegue healthcheck inside-container di default tramite `docker compose exec -T`, evitando falsi KO quando il compose Coolify non pubblica porte host.
- Aggiornati i QA statici Coolify/Docker.

## Nota produzione

In Coolify/staging/produzione reale lasciare `DATABASE_SYNCHRONIZE=false` e introdurre migrazioni versionate prima della RC. Il valore `true` e' pensato solo per il preflight locale con database effimero.
