# Report product strategy

## Posizionamento

ClientiAffidabili.it deve vendere report comprensibili, non semplici chiamate API. Il valore percepito nasce dalla trasformazione di dati tecnici in una risposta operativa:

> “Posso procedere con questo cliente/fornitore? Cosa devo controllare prima? Quale cautela applicare?”

Il report deve aiutare una decisione, ma non sostituire consulenza legale, fiscale, creditizia o investigativa.

## Promessa commerciale consentita

Promessa consigliata:

> “Ricevi una sintesi chiara dei segnali disponibili sull'azienda, con fonti, limiti e prossime azioni consigliate.”

Promessa da evitare:

> “Scopri se il cliente pagherà.”

## Value proposition

- Meno tempo perso tra visure, portali e dati frammentati.
- Lettura immediata anche per non tecnici.
- Prezzo chiaro prima dell'acquisto.
- Report con data, fonti, limiti e stato della richiesta.
- Storico consultabile nel proprio account.

## Differenziazione rispetto a marketplace API

Un marketplace API vende endpoint. ClientiAffidabili.it vende decision support.

| Marketplace API | ClientiAffidabili.it |
|---|---|
| Endpoint e payload | Report leggibile |
| Prezzo per chiamata | Prezzo per verifica/report |
| Developer-first | PMI/operatore-first |
| JSON/raw data | Sintesi, fonti, limiti |
| Integrazione tecnica | Checkout e report pronto |

## Report come asset commerciale

Il report deve essere progettato come un prodotto:

- copertina forte;
- sezione “in breve” sopra la piega;
- livello di attenzione visivo;
- segnali positivi/attenzione/blocco;
- dettagli verificabili;
- limiti chiari;
- CTA per acquistare add-on o monitoraggio.

## Upsell naturale

L'upsell deve essere coerente con il risultato:

- report base incompleto → proponi Check Pro;
- report Pro senza bilancio → proponi add-on bilancio;
- fornitore importante → proponi monitoraggio;
- esito ambiguo → proponi review assistita.

Nessun upsell deve creare paura artificiale o claim aggressivi.
