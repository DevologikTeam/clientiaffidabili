# Layout & Responsive Blueprint

## 1. Breakpoint

| Breakpoint | Uso |
|---|---|
| `mobile` < 640px | checkout, report e servizi devono essere one-column |
| `tablet` 640–1024px | griglie 2 colonne, sidebar non sticky |
| `desktop` > 1024px | griglie 3 colonne, dashboard con sidebar |
| `wide` > 1280px | container massimo, non allargare testi |

## 2. Layout landing

Struttura:

1. Hero con promessa e CTA primaria.
2. Trust bar con 3–4 segnali concreti.
3. Flusso in tre passaggi.
4. Servizi MVP.
5. Casi d'uso.
6. Pricing/checkout entry.
7. FAQ su limiti, fonti e uso lecito.

## 3. Layout catalogo servizi

Obiettivo: aiutare a scegliere, non mostrare un listino API.

Blocchi:

- filtro per obiettivo: “verificare azienda”, “ridurre frodi”, “controllare pagamenti”, “monitorare cliente”;
- card servizio con prezzo e tempo;
- confronto pacchetti;
- trust notice su uso lecito;
- CTA “Avvia verifica”.

## 4. Layout checkout

Ordine obbligatorio:

1. Riepilogo servizio.
2. Dati richiesti.
3. Uso consentito e conferma.
4. Prezzo, IVA, eventuali costi extra.
5. Checkout PSP hosted.
6. Esito ordine.

## 5. Layout report

Il report deve rispondere in ordine:

1. Qual è l'esito sintetico?
2. Quali dati sono stati verificati?
3. Quali segnali richiedono attenzione?
4. Quali fonti e limiti sono applicabili?
5. Cosa conviene fare adesso?

## 6. Dashboard

Sopra la piega:

- verifiche recenti;
- verifiche bloccate/in attesa;
- crediti/spesa del periodo;
- prossima azione consigliata.

Non mostrare grafici decorativi se non aiutano una decisione.
