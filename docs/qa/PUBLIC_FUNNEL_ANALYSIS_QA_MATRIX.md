# Public Funnel Analysis QA Matrix

## Scopo

Questa matrice verifica che lo sprint M2-A abbia prodotto una base sufficiente per progettare e sviluppare il funnel pubblico senza ambiguità.

| Area | Criterio | Stato |
|---|---|---|
| Segmenti | Segmenti target prioritari definiti | OK |
| JTBD | Jobs-to-be-done mappati | OK |
| Funnel | Architettura funnel sequenziale definita | OK |
| CTA | CTA hierarchy definita | OK |
| Copy | Messaggi consentiti/vietati definiti | OK |
| Trust | Segnali legal/compliance identificati | OK |
| Checkout | Precondizioni checkout definite | OK |
| SEO/GEO | Cluster e pagine iniziali definite | OK |
| Design system | Componenti mancanti per M2-P identificati | OK |
| Analytics | Eventi privacy-safe minimi definiti | OK |

## Checklist M2-P

- [ ] Wireframe landing.
- [ ] Wireframe scenario selector.
- [ ] Wireframe service detail.
- [ ] Wireframe report preview.
- [ ] Wireframe pricing/bundle.
- [ ] Wireframe FAQ/legal trust.
- [ ] Specifica componenti DS nuovi.
- [ ] Copy finale approvabile.

## Guardrail QA M2-S anticipati

- Landing responsive desktop/tablet/mobile.
- Header pubblico senza route interne di sviluppo.
- CTA primaria sempre visibile sopra la piega.
- Nessun claim assoluto.
- Uso lecito presente prima del checkout.
- Report preview chiaramente demo se usa dati fittizi.
- Footer con legal entry points.
- Performance e accessibilità da misurare con Lighthouse/axe quando ambiente pronto.
